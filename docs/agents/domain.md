# Domain docs

## Before exploring

Read root `GLOSSARY.md` and relevant decisions under `docs/adr/`.
If either is absent, proceed silently.
Create domain docs through domain-modeling when terms or decisions are resolved.

## Layout

This repo uses a single context:

- `GLOSSARY.md`: shared domain vocabulary.
- `docs/adr/`: architecture decision records.

## Vocabulary and decisions

Use glossary terms in issues, proposals, hypotheses, and test names.
If a needed concept is missing, note the gap for domain-modeling.
Explicitly flag proposals that contradict an existing ADR and explain why.
